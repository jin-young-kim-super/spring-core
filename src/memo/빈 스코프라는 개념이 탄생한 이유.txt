스프링에서 빈 스코프라는 개념을 만든 이유는 개발자가 늘 싱글톤 객체를 원하는 것이 아니라 상황에 따라서는 객체의 사용 목적이 다를 수가 있다.
-> 객체의 사용 목적이 다르기 떄문에 빈 라이프 사이클이 다르게 되므로 스코프라는 개념을 만들어서 서로 다른 빈 라이프 사이클을 적용하기 위함이다.
→ 이를 통해 객체의 특성에 맞는 생명 주기를 설계할 수 있고, 결과적으로 메모리와 서버 자원을 효율적으로 사용할 수 있다.

싱글톤 스코프:
애플리케이션 전반에서 공통으로 사용하는 객체이기 때문에 하나만 생성해서
애플리케이션 종료 시까지 컨테이너에서 관리되며 공유한다.
따라서 AnnotationConfigApplicationContext가 생성되는 시점에 컨테이너 내부에 빈 객체가 이미 생성되어 등록된다.

프로토타입 스코프:
매번 독립적인 상태를 가져야 하는 객체가 필요하기 때문에, getBean()으로 요청하는 시점에 컨테이너가 새로운 객체를 생성한다.
이때 의존관계 주입과 초기화 콜백까지만 수행한 후 클라이언트에 반환하고, 이후에는 컨테이너가 해당 객체를 더 이상 관리하지 않는다.

프로토타입 빈은 컨테이너 생성 시점에 객체가 생성되지 않고, BeanDefinition(빈 메타 정보)만 등록되어 있다가 요청 시점에 객체가 생성된다.
또한, 컨테이너는 프로토타입 빈의 생성 이후 라이프사이클을 관리하지 않으며,
객체의 소멸은 GC에 의해 이루어진다.
【즉, 개발자가 프로토타입 빈을 사용하는 목적은 요청 때마다 새로운 객체를 만들어서 사용할 필요가 있을 때이다】

웹 관련 스코프
・request: 웹 요청이 들어오고 나갈때 까지 유지되는 스코프이다.
・session: 웹 세션이 생성되고 종료될 때 까지 유지되는 스코프이다.
・application: 웹의 서블릿 컨텍스트와 같은 범위로 유지되는 스코프이다
