@autowired는 타입으로 빈을 조회 
→ 이것이 의미하는 것은, 만약 해당 타입으로 등록된 스프링 빈이 2개 이상일 시 의존 관계 주입의 대상이 2개 이상이 되는 경우도 있다는 것임
(@AutoWired는 이 경우 다음 전략으로 해당 필드명을 빈 이름으로 가진 빈을 스프링 컨테이너에 찾아서 의존관계를 주입)

@AutoWired에서 의존관계가 빈이 2개 이상 조회는 경우의 전략(즉, 조회 되는 빈이 2개 이상이며, 의존 관계로 딱 1개의 빈만 주입돼야 할 떄!)
・@Qualifier(주로, @Primary를 자주 사용 : @Qualifer는 코드가 많이 들어가는 반면 @Primary는 딱 1줄이면 된다)
・@Primary(가장 많이 사용, 그러나 @Qualifier가 수동 설정인만큼 우선권은 더 높다.)

@Qualifier vs @Primary
보통, DBConnection 인터페이스에 메인 데이터 베이스 커넥션을 획득하는 객체와 서브 데이터 베이스 켜넥션을 획득하는 객체가 있다고 하자.
이때 필요할 때마다 객체를  @Component나 @Bean에 의해서 빈 등록하고 하는 것이 번거로울 수가 있다. 또한 서브 데이터 베이스 커넥션이 사용률이 적기 때문에 만약에 의존관계 주입 대상이 아닌 경우 코드를 일일이 삭제를 해버리면 나중에 필요할 때 또 똑같은 코드를 작성해야 한다.
그래서 @Component와 @Bean을 통해서 둘 다 빈 등록을 해서 메인 데이터 베이스 커넥션일 때에는 @Primary를 붙여 주고, 서브 데이터 베이스 커넥션가 의존 관계로 주입되야 할 때에는
@Qualifier로 서브 데이터 베이스 커넥션을 의존 관계로 주입한다고 한다.그럼 @Qualifier가 @Primary보다 우선권이 높기 때문에 서브 데이터베이스 커넥션이 의존관계가 등록된다.
이렇게 @Primary와 @Qualifer를 사용하면 의존 관계가 2개 이상 조회 시 편안하게 의존관계로 주입할 빈을 선택할 수가 있고, 의존 관계가 아닌 빈을 삭제하거나 하는 번거로움이 없다
(단, 팀원들한테 이런 방식으로 사용할 것을  반드시 공유해야 한다)
※나중에 학습하겠지만, 2개 전부 의존관계로 필요할 때에는 List, Map으로 받으면 된다.
