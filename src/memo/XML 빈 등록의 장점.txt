XML 설정 사용의 장점
-> XML을 사용하면 컴파일 없이 빈 설정 정보를 변경할 수 있다

ex) 
@Configuration
public class AppConfig {

    @Bean
    public MemberService memberService() {
        return new MemberServiceImpl(memberRepository());
    }

    @Bean
    public MemberRepository memberRepository() {
        return new MemoryMemberRepository();
    }
}
여기서 MemberService가 사용하는 구현체를 바꾸고 싶다고 해봅시다.
return new MemoryMemberRepository();를
return new DbMemberRepository();로 변경해야 합니다.
그러면 Java 소스 코드가 변경된 것이므로 다시 컴파일해야 합니다(코드 규모가 크면 컴파일에 시간이 많이 걸린다)
즉,
Java 소스 변경
    ↓
컴파일
    ↓
.class 생성
    ↓
애플리케이션 실행


반면 XML에서는 설정을 코드와 분리할 수 있습니다.

<bean id="memberRepository"
      class="hello.core.member.MemoryMemberRepository"/>

<bean id="memberService"
      class="hello.core.member.MemberServiceImpl">
    <constructor-arg ref="memberRepository"/>
</bean>

여기서 구현체를 바꾸고 싶다면 XML만 수정하면 됩니다.
<bean id="memberRepository"
      class="hello.core.member.DbMemberRepository"/>

Java 코드는 전혀 수정하지 않았습니다.


따라서 [이미] 컴파일된 [.class 파일]을 그대로 두고 XML 설정 파일만 변경해서 Spring이 어떤 객체를 생성할지 바꿀 수 있습니다.
             XML Config
                 │
                 ▼
        설정 변경 → 컴파일 불필요
